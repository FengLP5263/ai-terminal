# Git panel

[简体中文](git.md) | English

Requires an installed Git for Windows. The name, path and Git summary share one header row, following the font selected in ai-terminal settings and current zoom; metadata shortens when space is limited. The branch icon uses Microsoft Codicons at the same text size. The summary shows the branch, `+added lines` and `−deleted lines` for the repository containing the current directory. Click the branch to toggle the right panel; drag its left edge to resize it. The workspace saves the open preference, and panel operations keep the terminal running.

Changes and expanded commits share compact single-row lists with file-type icons. Status follows the relative path; hover for the complete path and per-file line totals. Expanded icons align with the left edge of commit text. The columns describe the index and working tree; `??` means untracked. History shows commits reachable from the current HEAD, including merged history, and follows branch changes. Read 50 commits initially, then use Load more commits up to 300. A compact dot-and-line timeline shows history order. Hover for the author, UTC timestamp, full message and line totals; the card footer shows a commit icon and seven-character abbreviated ID, while copy controls on the card and row copy the full commit ID. Click a commit to expand changed files, then click again to collapse. File statuses are A/M/D/T; hover a file for its full path and line counts.

Commit details load on demand in the background when hovered or expanded. Only the current and expanded details are retained in bounded memory; changing directories cancels old requests. Root commits show initial files, empty commits explicitly show no file changes, and merge commits compare against their first parent with a visible label. Renames appear as deletion and addition; binary files have no line counts. Display at most 500 files while totals include all queried results, with a limit notice. Failed reads can be retried after expanding. The timeline shows history order rather than multi-branch topology.

Line totals are net changes against HEAD, combining staged and unstaged changes without double counting. New untracked text contributes additions. An unborn repository counts current file contents as additions. Binary files have no line counts. Files with content-filter attributes (such as Git LFS) do not run their filters; their counts are unavailable and totals are marked partial. Untracked files over 1 MiB each, beyond an 8 MiB read budget, or not regular files are marked unavailable. The file list is capped at 500 entries; exceeding it marks totals partial, while tracked-file totals still come from Git. Changes inside submodules are excluded. These are neither per-commit statistics nor comparisons with remote branches.

Windows directory notifications trigger coalesced background refreshes, filtering Git-ignored build events and Git reflog, lock and object writes; notification overflow triggers a full recovery read. Changing directories and explicit Refresh query the repository. With healthy monitoring, prompts, focus and opening the panel reuse current results. If monitoring is unavailable or a read fails, those actions trigger fallback at most once every two seconds, without idle polling. Reading status stays inside the existing refresh button instead of inserting a row. Non-repositories, missing Git, unavailable directory monitoring and query failures have explicit messages. Retained stale data after failure can be refreshed manually. There is no periodic scan or continuous idle repaint.

This version reads local branches, status and history. Staging, committing, fetching, pushing and switching branches remain terminal operations. Queries do not access the network, store file contents or credentials, modify Git configuration, bypass repository ownership checks, or execute repository hooks, external diff, textconv or content filters. Lazy fetching of missing objects and transport protocols are disabled. Each Git command has a six-second timeout and a 2 MiB output cap; exceeding either reports failure while the terminal stays usable.

Implementation references: [Git status](https://git-scm.com/docs/git-status), [Git diff](https://git-scm.com/docs/git-diff), [Git log](https://git-scm.com/docs/git-log).

Click a file in an expanded commit to open a read-only unified diff in the main area, retaining the right panel. Close it to return to the original terminal. Old/new line numbers distinguish sides; only row backgrounds and +/− markers use the existing application green/red. Code keeps normal body text colors and line numbers keep the secondary text color. Unchanged content is included from the first through the last line rather than limiting the view to changed excerpts; mode-only changes also show the file body. Only committed objects are read against the first parent or an empty root; uncommitted work is excluded. Binary/no-text differences have explicit messages. The view virtualizes visible rows, retains one file result and cancels old reads on directory changes, close or new requests; no disk cache is written. Display is capped at 20,000 lines and 4,000 characters per line with a truncation notice. Queries keep the six-second/2-MiB limits.

File names/extensions select built-in Syntect grammars without reading or executing project syntax scripts. JSON distinguishes keys, strings, numbers and language constants; Markdown distinguishes headings, lists, emphasis, links and code blocks. Common code uses bundled grammars; unknown types use plain text. Source spaces are preserved and tabs use four-column stops. Indent guides follow inferred existing indentation, defaulting to two columns for JSON/JS/Markdown and four for others, without reformatting files. Raw @@ ranges and modes occupy no body rows; modes and no-final-newline metadata are available on the title hover. Old/new multiline states are independent, with colors cached only for the current file. A two-second soft budget, 100,000 tokens and 256 spans per line bound preparation; fallback is plain text. Only visible rows are laid out, with no extra idle repaint.

The open committed file retains a gray background and thin blue marker in the right panel, matched by full commit ID plus path. Hover does not change selection; loading, errors, file switches, close and directory changes stay synchronized. File reads require valid UTF-8 and handle a first-line UTF-8 BOM. Invalid bytes report an error instead of silently inserting replacements. Validly encoded history that already contains corrupted text is displayed faithfully without guessed repair or repository changes.

File-body emoji use the existing Windows native color renderer, preserving complete graphemes for skin tones, ZWJ, flags, keycaps and variation sequences without changing source characters. Explicit text variants remain ordinary text. Code syntax colors stay independent of diff backgrounds, and only visible rows are laid out.

Files in Changes also open read-only diffs, labeled “Local changes”. They compare the current file with HEAD, combining staged and unstaged changes; untracked files and new files without HEAD show full additions, while removed content shows deletions. `??` reads “Untracked” with an explanation that it has not been added to Git; other descriptions distinguish staged/unstaged states and conflicts. The current file keeps its gray background and thin blue marker, separately from the same historical path. Repository events or manual refresh snapshots update an open working file; repeated clicks reuse results, and reverting to clean closes the obsolete diff, with no polling. Reads prepare only in memory, do not change the index or follow symlinks/junctions, and reuse the encoding, limits and external-program restrictions above. Editing is unavailable.

0.8.0 preview: the panel header contains only the repository name and Refresh/Close, without a separate Git title or duplicate branch/totals. Branch and line counts remain in the terminal header; no Git placeholder is shown without a repository snapshot. Untracked rows use a green U, with the full localized explanation on hover and distinct staging/conflict descriptions.

0.8.0-preview.2 uses the two-face 0.5.2+bat-0.26.1 extended syntax set with Oniguruma for PowerShell (ps1/psm1/psd1), CMD/batch, Bash, Python, JS/JSX, real TS/TSX, Dockerfile, TOML, INI, environment files, YAML, JSON/JSONC and Markdown. Language rules distinguish keywords, variables, parameters, types, commands, strings, numbers and comments; individual grammars need not classify every identifier. Recognizes .bashrc/.zshrc, Dockerfile.dev, .env.production and in-memory shebangs for extensionless scripts without opening other files or running interpreters. Old/new multiline states remain independent, preserving budgets, plain-text fallback, source text, indentation and diff backgrounds.
