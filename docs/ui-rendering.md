# 界面与跨屏渲染核查

简体中文 | [English](ui-rendering.en.md)

## 原因与实现

- 收起侧栏的会话块固定为 44×44 逻辑像素，头像居中；滚动条位于旁边的预留空间，鼠标离开侧栏后透明。不要从滚动区当前可用宽度回推行高：滚动条出现时会减少 7 个逻辑像素宽度，刚好溢出时会触发行高缩小→内容放得下→滚动条消失→行高变大的循环。此问题在 preview.1 被复现，preview.2 改用独立于滚动条的固定尺寸。
- OpenAI／Claude 源图为 640×640。直接以双线性过滤缩小到约 20 个逻辑像素会丢失细线；现在按实际物理尺寸做面积过滤，整数像素对齐。每种头像最多缓存 12 个尺寸，侧栏与浮窗共享，不在每帧重采样。
- Windows 表情字体的行框、基线及自然宽度与 Hack 不同。原来的单元格裁切会切掉窄字符表情及模式标识。现在完整缩放原生表情图块，允许利用紧随的空白格；不移动模拟器坐标，VS15 仍按文字处理。
- 浮窗与主窗口可处于不同 DPI 的屏幕。preview.2 仍将保存的位置反复转成窗口定位命令，并以异步视口坐标推算物理位置，可能与 Windows 拖动及 DPI 切换互相干扰。preview.3 将观察与定位分开：仅创建、缩放或会话数改变时主动定位；位置通过自身 HWND 的物理矩形读取。`floating_native.rs` 只在自身 UI 线程安装原生窗口子类，待后端处理完 DPI／尺寸通知后合并投递尺寸核对，原生拖动期间推迟主动定位，销毁时释放。没有空闲轮询，不扫描其他进程或控制用户窗口。
- 收起侧栏的三个工具按钮与会话共用 44×44 占位、32 点圆形底座及 20 点图标，纵向间隔 4 点；展开侧栏保留紧凑的普通工具按钮。
- 会话色保留原有序列化枚举，更新柔和配色与选中边框。状态颜色集中在 `src/chrome.rs`，侧栏、浮窗与连接提示共用；未读完成点的消失规则不变。

## Codex 的代理入口提示

`← for agents` 不是终端固定装饰。Codex 0.164.0 的代理总览需要共享后台服务；本项目注入 `--no-daemon` 后，Codex 不提供这个入口。上游 [CLI 定义](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/tui/src/cli.rs)与[启动分支](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/cli/src/main.rs)明确区分两种模式。

2026-11-03 用户明确选择优先保留准确的状态提示，暂不启用共享 agents 入口。因此保留独立模式与会话级 hook，不伪造提示，也不改用户级 Codex 配置。共享代理总览仍是待接入能力，不能列为已修复。

进一步核对时，本机 CLI 已为 0.166.0；该版本启动源码仍会因 `--no-daemon` 或不兼容的会话级 `-c` 配置跳过共享后台。因此，仅删除一个参数不足以恢复入口。后续接入必须同时验证多终端状态归属、对话切换和关闭回收，不能牺牲已验证的状态提示。本次版本查询与源码核对不是 0.166.0 的真实模型回合验收。官方命令边界见 [开发命令](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。

## 验证边界

侧栏交互回归覆盖展开／收起、方形选中框、悬停外隐藏、滚轮及拖动、未读消除。原生文字回归检查窄表情边缘未被裁掉，并保留组合表情与光标测试。

`workspace_probe` 提供界面截图；`island_move_probe` 使用至少两块真实显示器反复移动自己的浮窗，覆盖多档缩放、原生客户区大小和 PNG。`island_zoom_probe` 保留屏幕居中与固定屏幕缩放检查。命令见 [脚本目录](../scripts/README.md)。这些探针使用合成会话；真实 CLI 启动核查不提交模型请求，也不代表长期任务已验收。

2026-11-03 本机检查：146 项 Rust 回归（含新增的细线保留和窄表情裁切检查）、13 项 Python 回归、治理与 Clippy 通过；Release 原生 smoke 的三个 PTY 已回收。跨屏探针在 150%／250% 系统 DPI 下完成七阶段移动与缩放，逐阶段截图中十个头像完整。全屏末行探针的四档缩放检查通过。真实 Codex 未发送输入与 Claude Code 2.1.317 手动模式截图已核查，暂停图标完整；Claude 在未信任目录首次受阻，未自动确认信任，改在已有可信目录进行检查。原生探针为开发构建，正式程序 smoke 为 Release，不将这些结果当作长时间负载数据。

preview.2 追加核查：修复前新增测试在七个会话、550 点高的窗口上失败，首行在 51×51 与 44×44 之间切换；修复后侧栏九项回归通过。临界测试覆盖 7／8／10／12 个会话、71%／100%／121%／142% 缩放、连续静止与悬停，以及空闲时无立即重绘循环。原生 threshold 模式经过初始、缩放和窗口重设三阶段，81 次连续几何比较稳定，三张截图已核查。

preview.3 追加核查：跨屏探针分别发出原生进入／退出移动通知，再程序化跨越两块真实显示器，检查移动后多帧位置保持与异常放大后的尺寸恢复。它不模拟 Windows 鼠标模态循环，结果明确标记 physical_mouse_drag=false。两屏各自的缩放居中、浮窗关闭重开和侧栏临界布局检查通过，截图已查看；本机 Computer Use 原生管道不可用，真实鼠标拖动仍由用户独立验收。

preview.4 原因补充：所用 winit 0.30.13 的原生拖动路径会自行重算建议矩形并向旧显示器推回；[上游问题 4600](https://github.com/rust-windowing/winit/issues/4600) 记录了相同的 DPI 反馈问题。根据 [Microsoft 说明](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged)，本地补丁在原生移动时直接采用系统矩形，主窗口与浮窗同时覆盖；保留非拖动分支。浮窗在移动期间也不再额外改大小。展开侧栏的会话卡片左右留白保持一致。新探针在移动状态下跨 DPI，比较系统建议与实际矩形并记录递归深度；不将其误称为真实系统鼠标拖动。

0.4.4 定版：2026-11-03 用户已确认 preview.4 的本机真实跨屏拖动正常。该批检查包含 150 项 Rust、13 项 Python 回归及 Release smoke；保持移动状态的双屏探针记录 14 次 DPI 事件、最大递归深度 1、建议／实际矩形误差 0、移动期间额外尺寸写入 0。公开 README 截图另用 Release 组件和固定合成内容生成，不代表真实模型回合或 Windows 10 远程实机复测。
