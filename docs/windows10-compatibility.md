## 原生控制台对照

同一 Windows 10 19045、同一测试 EXE：系统旧 ConPTY 丢失 ALT_SCREEN／鼠标模式，应用内滚轮测试失败；添加固定版本的微软签名组件后，滚动和左键拖选均通过。这确认的是控制台协议兼容性问题，不是 #12 原始现象的直接复现。

运行组件为 Microsoft.Windows.Console.ConPTY 1.25.260930003，来源、哈希、最低系统版本和原始 MIT 许可证见 [assets/windows/conpty](../assets/windows/conpty/README.md)。构建与新格式 ZIP 包含 `conpty.dll` 和 `OpenConsole.exe`，不安装系统服务或替换 Windows 文件。

## 验证范围

- 治理、fmt、Clippy、144 项 Rust 测试、10 项 Python 测试通过。
- 本机与 Windows 10：三会话原生 smoke、公开 CLI 入口、四档输入区回归、原生标题栏、应用内滚动与拖选通过；测试 PTY 已退出。
- Windows 10：30 个合成会话的侧栏，以及浮窗最小化／恢复／关闭和重开检查通过。
- 完整本地 ZIP 回读校验通过，manifest format_version=2、dirty=true、published=false。可执行文件版本仍为 0.4.2，不能当作正式新版发行包。
- 没有真实模型请求。CLI 版本核查、合成全屏响应、合成状态和真实模型任务必须分开描述；这些测试不证明真实 Agent 长时间多轮会话全部兼容。
- 本机截图已复核；Windows 10 原生 PNG 通过像素检查，标题栏和 151.13608% 缩放输入区的局部截图已回读、校验 SHA-256 并完成视觉复核；完整原图保留在远程独立目录。测试二进制进程已全部退出，系统的应用／系统浅色设置均保持为 1。

UU 曾返回 `environment_check_failed (code 6)`。用户清理历史终端并新建会话后，远程命令恢复；本次新增测试会话结束后已退出，只保留用户自己的新会话。该现象涉及 UU 终端会话状态，不能仅凭通用错误码认定是控制端或被控端的问题。截图回读脚本另修正长命令输入与回显解析，不属于产品代码修复。

原生证据只保存在忽略的 `output/` 和远程独立临时目录，不提交用户路径、对话、凭据或截图。复跑命令见[脚本目录](../scripts/README.md)。#12 后续应增加真实 CLI 配合回环假响应的连续多轮及最大化场景，并记录输入区与终端尺寸；不自动接受项目或 hook 信任。

## 0.4.3 本机预览

用户在 Windows 10 的上述预览中确认基本功能正常后，版本清单和锁文件更新为 0.4.3，在本机重新构建并启动。治理、fmt、Clippy、144 项 Rust 测试、10 项 Python 测试和三会话原生 smoke 通过；本地预览包已回读校验，窗口标题为 `ai-terminal 0.4.3`，启动命令退出后仍响应正常。

预览使用 `output/previews/0.4.3-<timestamp>/` 下的独立会话数据和启动入口；保留已运行的 0.4.2 实例，不修改其配置。该预览制品当时的 manifest 为 dirty=true、published=false，启动预览这一步没有创建标签或远端发行。Windows 10 验证使用的是改版本号前的同批修复构建；基本功能试用不能代替 #12 原始条件的针对性复现。用户随后确认本机 0.4.3 试用未见明显问题，并授权正式发版；正式制品须重新从经 PR 合并的干净提交构建。
