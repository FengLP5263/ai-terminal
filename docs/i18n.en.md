# Bilingual documentation policy

[简体中文](i18n.md) | English

The project serves contributors using different languages. Existing Chinese text keeps its path; the English counterpart uses `.en.md`, for example `README.md` / `README.en.md` and `SKILL.md` / `SKILL.en.md`. Both languages should faithfully express the same facts, commands, permissions, and verification limits, without relying on literal machine translation. Link both directions at the top. AI tools continue to discover the original `AGENTS.md` and `SKILL.md`; English counterparts support readers without changing tool discovery.

Create or update both languages and relative links in the same change for current project-authored documentation. Keep commands, arguments, paths, versions, hashes, and license names consistent. Repository governance checks pairing and reciprocal links; automation cannot prove semantic equivalence, so review remains necessary.

After reviewing both languages, run `python scripts/check_bilingual.py --record` from the repository root and commit the updated digests with both documents. Governance checks pairs, links, and digest changes; hashes flag edits but do not replace human translation review.

Keep third-party licenses, upstream copyright/original notices, and generated material verbatim; do not rewrite legal text. GitHub issue/PR templates are bilingual on the same page. `CLAUDE.md` is a tool entry pointing to `AGENTS.md`, not a separate copy. Historical version records retain their existing paths and contemporary evidence; see [translation status](i18n-status.en.md). Local vendor patch notes are bilingual; original upstream material and licenses are preserved.
