# UI and cross-monitor rendering checks

[简体中文](ui-rendering.md) | English

## Causes and implementation

- Collapsed-sidebar tiles are fixed at 44×44 logical pixels with centered avatars. The scrollbar uses the adjacent gutter and becomes transparent outside the sidebar. Never derive row height from the scroll area's current available width: showing the scrollbar removes 7 logical pixels, causing an overflow→shorter rows→content fits→hidden scrollbar→taller rows loop near the threshold. Reproduced in preview.1; preview.2 uses a fixed size independent of scrollbar visibility.
- OpenAI/Claude source images are 640×640. Direct bilinear reduction to roughly 20 logical pixels loses thin strokes. Area filtering now prepares the physical display size and aligns it to integer pixels. Each avatar caches at most 12 sizes, shared by the sidebar and floating window; it is not resampled every frame.
- Native glyph atlas keys contain only text, font size, weight/italic, emoji style and pixel dimensions, not foreground/background colors. Color is supplied by mesh vertex colors at draw time. Animated TUI gradients, blinking and per-frame recoloring therefore reuse the same glyphs instead of creating atlas entries per color. When an atlas page fills, only the oldest page is retired and its texture handle is kept until a later frame, so shapes already recorded this frame never sample an early-freed texture and the whole atlas is no longer cleared and rebuilt.
- Windows emoji faces have different line boxes, baselines, and natural widths from Hack. Cell clipping cut off narrow emoji and mode badges. Native emoji tiles now fit the complete cluster and may use an immediately following blank cell. Emulator coordinates do not move, and VS15 retains text presentation.
- The floating bar and main window can occupy monitors with different DPIs. Preview.2 still converted saved positions back into placement commands repeatedly and inferred physical positions from asynchronous viewport coordinates, which could conflict with Windows dragging and DPI transitions. Preview.3 separates observation from placement: only creation, zoom or session-count changes request placement; physical position is read from our own HWND. `floating_native.rs` installs a subclass only on our UI thread, coalesces client-size reconciliation after the backend handles DPI/size events, defers placement during native movement, and releases state on destruction. There is no idle polling, other-process scanning or control of user windows.
- The three collapsed-sidebar controls share session geometry: 44×44 tiles, 32-point circular surfaces, 20-point glyphs and 4-point vertical gaps. Expanded-sidebar controls retain their compact normal size.
- Session-color serialization keeps its existing enum. Refresh softer colors and selected borders. Centralized status colors in `src/chrome.rs` serve the sidebar, floating rail, and connection hints; unread-completion acknowledgment stays unchanged.

## Verification boundaries

Sidebar interaction tests cover expanded/collapsed tiles, square geometry, hidden idle scrollbars, wheel/thumb dragging, and unread acknowledgment. Native text tests check unclipped narrow-emoji edges while retaining composed-emoji and cursor coverage.

`workspace_probe` captures UI screenshots. `island_move_probe` requires at least two physical monitors and repeatedly moves its own floating window, checking zoom levels, native client dimensions, and PNGs. `island_zoom_probe` retains centering and fixed-monitor zoom coverage. Commands are in the [script directory](../scripts/README.en.md). These probes use synthetic sessions. Actual CLI startup checks submit no model requests and do not establish long-running task acceptance.

Local checks on 2026-11-03: 146 Rust regressions (including new thin-stroke and narrow-emoji clipping coverage), 13 Python regressions, governance, and Clippy passed. Release native smoke reclaimed all three PTYs. Seven cross-monitor move/zoom stages ran at 150%/250% system DPI; screenshots show all ten avatars. Four fullscreen final-row zoom checks passed. Actual Codex unsubmitted input and Claude Code 2.1.317 manual-mode screenshots were inspected; the pause icon is complete. Claude initially stopped at an untrusted directory; trust was not approved automatically, and checks moved to an existing trusted directory. Native probes use development builds; application smoke uses Release. These results are not long-duration load measurements.

Additional preview.2 checks: before the fix, the new seven-session/550-point-height test failed with the first row alternating between 51×51 and 44×44. All nine sidebar regressions pass after the fix. Threshold cases cover 7/8/10/12 sessions, 71%/100%/121%/142% zoom, consecutive idle and hover frames, and absence of an immediate idle repaint loop. Native threshold mode checks initial size, zoom, and window resizing: 81 consecutive geometry comparisons were stable, and three screenshots were inspected.

Additional preview.3 checks: the cross-monitor probe sends native enter/exit movement notifications separately, then moves programmatically across two physical monitors, checking multi-frame position retention and recovery from an oversized client. It does not simulate the Windows mouse modal loop and explicitly records physical_mouse_drag=false. Per-monitor zoom/centering, floating close/reopen and sidebar threshold checks passed, and screenshots were inspected. The local Computer Use native pipe was unavailable; physical mouse dragging remains separate user acceptance.

Additional preview.4 cause: the winit 0.30.13 native-drag path recalculates the suggested rectangle and nudges it toward the old monitor; [upstream issue 4600](https://github.com/rust-windowing/winit/issues/4600) records the same DPI feedback problem. Following [Microsoft guidance](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged), the local patch directly applies the OS rectangle during native movement for both main and floating windows, retaining the non-drag branch. The floating bar also stops extra mid-move size repairs. Expanded-sidebar cards retain equal side insets. The new probe crosses DPI boundaries with move state active, compares OS-suggested/actual rectangles and records nested depth; it is not described as physical system mouse dragging.

0.4.4 acceptance: on 2026-11-03 the user confirmed physical cross-monitor dragging works locally in preview.4. Checks for this batch include 150 Rust and 13 Python regressions plus Release smoke. The held-move two-monitor probe recorded 14 DPI events, maximum nested depth 1, zero suggested/actual rectangle error and zero extra mid-move size writes. Public README screenshots separately use Release components and fixed synthetic content; they are not real model turns or a repeat Windows 10 remote-hardware test.

## Follow-up: native lifecycle and adjacent mode badges

After 0.4.4, the user requested agents-entry integration. Codex 0.166.0 [terminal_program_status.rs](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/tui/src/terminal_program_status.rs) emits explicit OSC 7501 lifecycle. The manager consumes a finite state enum from the current PTY without default overrides that disable the shared server; older CLIs can explicitly use `codex --no-daemon` and legacy hooks. A 32-state epoch-scoped queue coalesces wakes and is drained in background logic, without silence, bell or transcript heuristics. Native mode does not control the shared service or accept hook trust; the runtime record covers recovery-ID and exit semantics. The earlier deferral remains 0.4.4 history, not the new development mode.

Claude's adjacent narrow triangles previously received different visual widths: the first used one cell because another icon followed, while the final icon expanded into a following blank and used two, producing different native raster scales. The new regression first failed with widths 1/2; adjacent badges now have equal widths. Isolated badges, compound emoji and VS15 behavior remain intact.
