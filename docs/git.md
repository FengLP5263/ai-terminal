# Git 面板

简体中文 | [English](git.en.md)

需要已安装的 Git for Windows。名称、路径和 Git 摘要位于顶部同一行，跟随 ai-terminal 设置中的字体及当前缩放；空间不足时缩略。分支图标使用微软 Codicons，并与文字同档尺寸。Git 摘要显示当前目录所属仓库的分支、`+新增行数` 与 `−删除行数`；点击分支打开或收起右侧面板，拖动面板左边缘调整宽度。打开状态随工作区保存，操作不重启终端。

“更改”与展开的提交共用带分类文件图标的紧凑单行列表；状态码在路径之后，悬停查看完整路径及逐文件行数。展开文件的图标与提交说明左缘对齐。状态的两列分别对应暂存区与工作区，`??` 表示未跟踪。“提交历史”显示当前 HEAD 可达的提交，含合并进来的历史；切换分支后随之更新。每次读取 50 条，点“加载更多提交”逐次增加，最多 300 条。历史使用圆点连线的紧凑时间线；悬停查看作者、UTC 时间、完整提交说明及增删统计，卡片底部显示提交图标及 7 位短 ID；提示卡片与行末的复制按钮都复制完整提交 ID。点击提交展开更改文件，再次点击收起，文件状态为 A／M／D／T，悬停文件查看完整路径和行数。

提交详情在悬停或展开时按需后台读取，只保留当前详情和已展开详情的有界内存数据；切换目录取消旧请求。根提交展示初始文件，空提交明确显示无文件更改，合并提交相对第一父提交比较并明确标注。重命名按删除与新增分别展示；二进制不计行数。文件最多显示 500 项，合计包含全部查询结果，超出时提示；查询失败可展开后重试。时间线表示历史顺序，不绘制多分支拓扑。

增删行数是相对 HEAD 的净变化，合并已暂存和未暂存修改，避免同一改动重复统计；新增的未跟踪文本计入新增行数。新仓库尚无 HEAD 时按当前文件内容统计新增。二进制不统计行数；带内容过滤属性的文件（如 Git LFS）不运行过滤器，标注未统计并使总数显示不完整。未跟踪文件单个超过 1 MiB、总读取超过 8 MiB 或非普通文件会标注未统计。文件列表最多 500 项，超过时显示统计不完整；已跟踪文件的总行数仍取自 Git。子模块内部变化暂不展示。此处不是提交前后统计，也不是远端分支比较。

目录变化通过 Windows 通知在后台合并刷新，过滤被 Git 忽略的构建事件以及 Git 日志、锁文件、对象写入；通知溢出时完整补查。切换终端目录与面板“刷新”会查询；健康监控下，提示符、重新聚焦和打开面板复用当前结果。监控不可用或读取失败时，这些操作最多每两秒补查一次，不会空闲定时扫描。读取提示位于既有刷新按钮，不新增状态行。不在 Git 仓库、未安装 Git、目录监控不可用或查询失败会明确提示；失败时保留的旧数据可手动刷新。没有定时扫描或空闲持续重绘。

此版本只读取本地分支、状态和历史，不提供暂存、提交、拉取、推送或切换分支按钮；这些操作仍在终端执行。查询不访问网络，不保存文件正文或凭据，不修改 Git 配置，不自动绕过仓库所有权检查，也不执行仓库 hook、外部 diff、textconv 或内容过滤器；禁用缺失对象的延迟获取及传输协议。每条 Git 查询有 6 秒超时和 2 MiB 输出上限；超过时提示失败，终端继续可用。

实现依据：[Git status](https://git-scm.com/docs/git-status)、[Git diff](https://git-scm.com/docs/git-diff)、[Git log](https://git-scm.com/docs/git-log)。
